# TH-1401 릴리즈 큐레이션 광고 깜빡임 조사

기록: 2026-10-08. 사용자 제보에 따라 릴리즈 실홈의 카드 사이 AdMob을 조사했다. 아래는 에뮬레이터 QA 세션의 화면·프레임·SDK 이벤트 관측과 현재 코드의 읽기 전용 확인을 구분한 기록이다. 이번 조사에서는 제품 코드·SDK 버전·광고 설정을 변경하지 않았다. 릴리즈 검증의 전체 범위는 [13 릴리즈 에뮬레이터 검증](13-release-emulator-verification.md)에 있다.

## 조사 조건과 증거

- 로그인한 릴리즈 실홈에서 가로 광고를 충분히 노출하고 정지 영상을 기록했다. 설치 APK와 조사한 소스는 같은 버전 `4.26.0`이며 Google Mobile Ads SDK는 기존 `24.9.0`이다.
- 첫 정지 구간은 SwiftShader GPU 환경, 비교 구간은 AVD 데이터와 로그인 상태를 보존한 채 `-gpu host`로 재시작한 환경이다.
- 비교 녹화 전에는 SelfCare 소재가 보였지만, SDK가 18:23:12에 자동 갱신을 완료해 18:23:17 녹화 시작 시에는 Classen 소재였다. **두 녹화는 GPU 환경뿐 아니라 소재도 달라 동일 소재의 통제 비교는 아니다.**
- 영상은 로컬 `build/harness/th1401-release/` 아래에 있다. 인증 정보·원본 SDK 응답·광고 단위 값은 이 문서에 기록하지 않는다.

| 증거 | 관측 조건·내용 |
|---|---|
| `build/harness/th1401-release/flicker-full-idle.mp4` | SwiftShader에서 광고를 충분히 노출한 정지 구간. 프레임 43~46에 약 1초 동안 소재 영역이 흰 공백으로 보였고 프레임 47에 같은 소재가 복귀했다. 테스트 광고 오버레이는 유지됐다. |
| `build/harness/th1401-release/flicker-host-idle.mp4` | host GPU의 20초 정지 구간. 프레임 1에 Classen 이미지, 프레임 11(약 2.5초)에 흰 fade, 프레임 12~14에 텍스트·사진의 순차 등장, 프레임 32에 사진 교체, 프레임 43(약 10.5초)에 다시 흰 fade가 관측됐다. 테스트 광고 표시·테두리·info 버튼은 유지됐다. |
| `build/harness/th1401-release/flicker-observations.json` | 최종 시각 대조. host 영상의 기기 시각 18:23:17~18:23:38 동안 `HomeCurationAdMob` 전체 이벤트는 빈 배열이며, GPU renderer는 Apple M4 Pro, color buffer/H.264 frame 오류는 각각 0회로 기록됐다. |

## 확인한 사실

- 앞선 일부만 노출된 광고의 18초 정지 구간에서는 해당 광고 영역의 프레임 변화가 0이었다. 광고 전체를 노출한 정지 구간에서는 위의 소재 영역 변화가 관측됐다.
- 초기 진단에는 같은 광고 ID의 짧은 `request/released` 반복이 있었지만, 사용자의 스크롤·탭 전환과의 상관관계는 확정되지 않았다. 이 흔적을 정지 중 깜빡임의 원인으로 사용하지 않는다.
- 정지 중 소재 공백 구간에는 초기 `request/released`가 없었다. 최종 시각 대조에서 host 녹화 구간의 `HomeCurationAdMob` 전체 이벤트가 0회였다. 따라서 그 구간에는 `request`, `released`, `loaded`도 없었다. 녹화 전 자동 갱신과 녹화 중 소재 변화는 서로 다른 시점이다.
- SwiftShader 진단에는 Vulkan color buffer 및 H.264 frame 오류가 관측됐다. host 비교 구간에서는 해당 두 오류가 각각 0회였다.
- 현재 renderer의 `request`는 `DisposableEffect` 진입의 `loadAd`, `released`는 종료의 `destroy`에서 기록된다. `onAdLoaded`는 이벤트 gate만 갱신하며 앱 UI를 흰색으로 비우지 않는다. 일반 재구성·시트 offset 변화만으로 주기적으로 `loadAd`, 크기 또는 alpha를 변경하는 앱 루프는 확인되지 않았다.
- Lazy 셀이 실제로 해제됐다 복귀하면 같은 ID도 새 광고뷰를 만들 수 있는 구조는 있다. 다만 이것만으로 이번 정지 구간의 소재 공백을 설명할 수는 없다.

## 현재 판단과 한계

- **추론:** host 영상에서는 광고 host의 고정 요소가 유지되고 새 로드 이벤트 없이 사진·텍스트가 순차 등장하며 약 8초 간격의 fade가 반복됐다. 이 구간의 흰 fade는 앱의 광고뷰 재생성보다 **소재 자체의 애니메이션일 가능성이 높다.** SDK 내부 구현이나 소재 원본을 조사하지 않았으므로 원인을 확정한 것은 아니다.
- **미확정:** SwiftShader의 일시 공백에는 GPU/소재 렌더링 문제가 관여했을 수 있다. host에서도 다른 소재의 fade가 관측됐고 두 환경의 소재가 달라 GPU 전환으로 문제가 해결됐다고 결론 내릴 수 없다.
- **미확정:** 최초 사용자 제보의 심한 깜빡임이 이번 정지 영상의 fade와 같은 패턴인지, 스크롤 시 광고 셀 재진입의 재로드인지 추가 확인이 필요하다. 짧게 이동한 수평 swipe도 native 광고 터치 경합·목록 경계 등의 원인을 확정하지 못했다.
- 18초·20초 결과는 각각의 관측 구간에 한정한다. 약 60초 SDK 자동 갱신의 모든 전환이나 실기기에서의 동작까지 검증한 결과가 아니다.

## 처리 상태

현 관측만으로 앱의 깜빡임 결함이나 수정 지점을 확정하지 않아 추가 제품 수정은 하지 않았다. 이 문서는 조사 기록이며 **원인 확정·문제 해결·최초 사용자 제보 재현 완료를 뜻하지 않는다.** 후속 확인은 최초 제보와 같은 조건·패턴을 식별하는 데 한정한다.
