# Agent Workflow

## Session Start

1. `AGENTS.md`를 읽는다.
2. 작업 범위에 맞는 `docs/context/` 문서를 확인한다.
3. Jira/feature 작업이면 `docs/features/`에 기존 문서가 있는지 찾는다.
4. 변경 전 `git status --short`로 사용자 변경사항을 확인한다.

## Execution And Questions

- 구현 요청은 승인된 범위의 수정과 검증까지 수행한다. 분석·검토·계획만 요청받으면 해당 산출물로 마치고 구현하지 않는다.
- 작업 범위와 별도 승인 단계를 구분한다. 수정 요청이 있어도 적용 Skill이 명시한 설계·구현 승인을 자동으로 충족했다고 해석하지 않는다.
- 저장소와 대화로 결정할 수 있는 기술적 세부사항은 기존 패턴에 맞춰 정한다. 답에 따라 결과가 실질적으로 달라지고 근거로 해결할 수 없는 사항만 질문한다.
- 질문을 기다리는 동안 해당 답에 의존하지 않는 승인된 작업을 계속한다. 명시적 승인 단계나 안정적인 baseline을 요구하는 단계는 충족될 때까지 보류한다.
- 테스트 실패는 원인과 영향 범위를 조사하고, 요청 범위 안에서 수정·재검증한다. 기존 실패와 새 회귀를 구분하며, 관련 없는 코드까지 고치지 않는다.
- 도구가 없으면 기존 Gradle/adb 등 동등한 경로를 확인한다. 사용자 지정 도구가 필수이거나 동등한 검증이 불가능한 경우에만 필요한 조치를 요청한다. 새 설치·의존성 변경에는 기존 승인 규칙을 적용한다.

## Approval Scope

- 승인 시 대상·내용·범위와 필요한 비용·환경 조건을 확인한다. 같은 조건으로 이미 받은 명시적 승인은 재사용하고, 조건이 실질적으로 바뀌면 해당 변경만 다시 확인한다.
- 승인된 설계·명세를 문서화하거나 계획을 세분화했다는 이유만으로 재승인받지 않는다. 새로운 정책·범위가 추가되면 별도로 확인한다.
- 계획 보고, 실행 방식 선택, 진행 보고를 새로운 승인 관문으로 만들지 않는다. 필요한 설계·구현 승인이 모두 충족된 실행 요청은 다음 단계로 이어간다.
- 외부 상태 변경, 버전·의존성 변경, 대규모 리팩터링, 포맷 전용 변경 및 destructive git 작업에 대한 `AGENTS.md`의 승인·보호 규칙을 유지한다. 일반적인 "진행해"를 대상이 정해지지 않은 외부 작업 승인으로 해석하지 않는다.
- 승인 대기 전 읽기 조사와 허용된 준비 작업으로 대상·영향·검증 계획을 구체화한다. 승인 없이 해당 변경을 먼저 실행하지 않는다.
- Skill 때문에 중단하거나 승인을 요청할 때는 실제 읽은 파일 경로와 해당 문구, 보류되는 단계, 계속할 수 있는 작업을 간결하게 설명한다.

## Feature Work

- 새 feature는 `docs/features/FEATURE-TEMPLATE.md`를 기준으로 문서를 만든다.
- 조사 결과와 구현 계획을 먼저 기록하고, 구현 후 verification을 채운다.
- Product/Server/iOS와 맞춘 정책은 feature 문서 또는 ADR에 남긴다.

## Documentation Updates

- 모듈 의존성이 바뀌면 `docs/context/module-dependencies-current.md`를 갱신한다.
- toolchain 또는 버전이 바뀌면 `docs/context/project-current.md`와 `AGENTS.md`를 확인한다.
- 검증 방식이 바뀌면 `docs/context/verification-matrix.md`와 `docs/harness/README.md`를 갱신한다.

## Completion Report

- 사용자가 요청한 결과와 필수 검증을 완료 기준으로 삼는다. 검토 횟수 제한은 조사 방식을 바꾸는 기준이며, 실제 결함이나 미충족 요구사항을 완료로 바꾸지 않는다.
- 독립적인 후속 작업으로 미룰 수 있어도 요청된 필수사항은 사용자 동의 없이 제외하지 않는다. 실행할 수 없는 필수 검증은 검증 미완료로 보고한다.
- 로컬 수정·검증만 요청받았다면 merge/push/PR 선택 없이 결과를 보고한다. 외부 실행이 요청 범위에 포함되면 준비를 마친 후 필요한 승인을 확인한다.
- `docs/context/verification-matrix.md`에 따라 검증하고 다음을 보고한다. 보고서·검증 산출물 경로와 결과에 영향을 주는 오류는 숨기지 않으며 민감정보는 제외한다.

- 실행한 검증
- 실행하지 못한 검증과 이유
- 남은 리스크 또는 후속 작업
